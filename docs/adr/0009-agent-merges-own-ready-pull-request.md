# A session may merge its own ready pull request where the repository opts in

A repository can set `MENTAT_AGENT_MERGE` to `on` in its committed `.claude/settings.json`, and then a session merges the pull request it opened once its reviews and CI pass on the head they covered; the setting is off by default, and with it off the maintainer merges every pull request as before. A pull request that changes a protected path (`.github/`, `.claude/` and the repository's `MENTAT_MERGE_WAIT_PATHS`) or that a reviewer marked `(high risk)` keeps waiting for the maintainer, and a change that removes or loosens a check of the repository's test command is always marked high risk. The merge hook passes exactly one command, `gh pr merge <N> --merge --match-head-commit <sha>`, so a session cannot merge another way, another pull request's commit or a moved head. Why: the maintainer's look is kept for the changes that can hurt, and routine ones stop waiting on it; whether that trade is right is each maintainer's call, so it is an opt-in per repository.

The protected list is fixed text, so a safety-relevant change outside it, such as a skill that tells agents what to do or a test that stops checking something, is not held by the list. Only review catches it, through the high-risk mark; a reviewer that misses it lets the change merge without the maintainer's look. The list therefore names the files that hold the safety nets (the hooks, the settings, the safety rules and their fixture, the changelog) and this repository's own change to any of them waits, so a session cannot widen its own permission by merging it.
