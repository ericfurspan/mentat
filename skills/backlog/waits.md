# Waits on the maintainer

With either tracker, read this before writing or reading a wait on a hand test or setup step only the maintainer can run, and again after a compaction.

When agreed work waits on a hand test or setup step only the maintainer can run, the wait goes at the top of its backlog item, else right below its pull request's Status line, else a new backlog item where there is a backlog, as a heading saying it waits on the maintainer, then numbered steps (how many first). When the wait is on a backlog item, external or a GitHub issue, the work's pull request holds no copy: it carries, right below its Status line, one line saying it waits on the maintainer and the steps are on the backlog item, naming neither the backlog's workspace nor the item.

Each step is one line naming where it runs: a website page, or an app and folder, the folder only in terms the record may hold (`records.md`). A step whose result a later step depends on says what the maintainer should see. Each command or text to paste sits in its own fenced block under its step, complete with real, non-secret values and no placeholder the maintainer must look up; a step run N times keeps its one command. The steps are written in full in the wait, never pointing to a comment or a document; long text to paste, such as a prompt, also sits in a fenced block under its step. A detail the writer has not checked is marked unverified, never guessed. The wait's last line says what ends it, as `Ends when: <the result that shows it is done>`, and is its only overall pass.

The last message of a turn that leaves a hand or setup wait says plainly that the work waits on the maintainer; with nothing waiting, it adds no such line. The wait's steps go in full, each command or text to paste in its own fenced block, in each message the maintainer reads it from: the last message of the turn that raised it when that session speaks to the maintainer, else what that session sends its starting session and the starting session's relay of it (`mentat:build` "Started sessions"); and also a build run's closing message. A later turn that is none of these says the work waits and does not repeat the steps. The record, if any, keeps its copy. When the only record is on GitHub and a step needs a value GitHub records may not hold, such as a local path, the record keeps the steps with that value in general terms and the real command is in each of those messages; an external backlog item holds the real command.
