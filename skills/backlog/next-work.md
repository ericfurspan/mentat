# The next-work ending

Read this when the maintainer's own instructions choose the "offer the next work" ending (`rules.md` "Ending finished work"), and again after a compaction.

- Claude Code never suggests ending the session or starting a new one unless the maintainer said the session is ending.
- Only the session the maintainer is talking to offers, in one `AskUserQuestion` prompt, when its own work has just finished: after a plan run with no item id, only next work it did not start (a plan run with one item id makes no offer and adds no Inbox line); after a build queue, in its final message, with nothing offered mid-queue and a yes never adding to the finished queue; after the maintainer says a pull request merged, once its item is marked done (the post-merge step in `../review/after-ready.md`, which the Claude-only path follows), never from a backlog listing's cleanup or while a queue runs; after triage that ends with no question, where an accepted item is offered for `mentat:propose`, never for building.
- An offer of agreed work that can start says what a yes authorizes: starting that batch, not merging open pull requests and not new scope. A Backlog item's offer says instead that a yes starts `mentat:propose` for that item in this session, which still asks its own agreement. A merge still waiting is named in one line, in plain words, without repeating a "Ready to merge: #N" line an earlier message gave.
- Its lookup reads the next agreed work (`mentat:backlog` "The order of agreed work") read-only, and reports one of: the backlog could not be read; no recorded order; agreed work all waiting on the maintainer; agreed work none of which can start (in progress, waiting on an unmerged pull request, or held by its start wait, `mentat:backlog` "Start waits"); no agreed work. It offers only an item that can start, naming each one it passed with its wait.
- When no agreed item can start (all waiting, none able to start, none at all, or no recorded order), the lookup then reads the open Backlog items read-only, in the Backlog order the tracker's adapter gives. It passes parked items, every item the finished work just planned (all of a whole-backlog plan's subject) or offered, items whose `## Current plan` next step is `/mentat:plan <id>`, whether a plan or triage recorded it, items holding only a decision for the maintainer, and agreed items, those carrying a `## Spec` or `## Agreed request` section. It names in one line the items with that next step, the decision-only items and each agreed item with `/mentat:build <id>`. It offers the first remaining item for `mentat:propose` in the one offer prompt, with a recommendation, never for building.
- In those cases, when the count of Inbox items triage would ask (`mentat:backlog` "Stages") is above zero, the ending adds one line with the count and `/mentat:triage` to type, not a question, whether or not a Backlog item is offered.
- It says nothing is waiting, in its own words with no fixed phrase, only when Todo, In Progress, Backlog and the Inbox were all read and are empty; parked items, items just planned and Inbox entries deferred with a Later note count as not empty. When work remains but nothing can be offered, it says in one line, in its own words, what remains. When any of those reads fails, the read of agreed work included, it says which, offers nothing and never reports empty.
- A session started by another session makes no offer; its ending goes to the session that started it.
- After "Stop here", "Stop" or a no, no offer is made that turn; a no declines that batch only.
- A yes to an offer of agreed work starts that build in this session, as `mentat:propose` "Starting a build" says; `mentat:build` still runs readiness, plan usage and the quick check.
- A yes to a Backlog item's offer starts `mentat:propose` for that item in this session, which still asks its own agreement; no second next-work ending runs in that turn.
