The maintainer has turned Codex off for the rest of this session. Until the maintainer says in chat to turn Codex back on, these replace the Codex review loop (`mentat:review`) with one Claude review, and the plan challenge (`mentat:plan` step 2) and `mentat weigh` (`mentat:propose`) with nothing; Claude Code's own view of a request still runs. Everything else in `rules.md` holds. After a compaction or a resumed session, Codex stays off; only the maintainer turns it back on, in chat. When they do, say in one line that Codex review is on again; that starts no review by itself. From then on the next review of any pull request, including one that had a Claude review round, goes through `mentat:review`: Codex reviews the head, and Grok reviews it too where it has not yet run on that pull request; a Claude review already running finishes and its findings are settled as usual.

When started, say in one line that Codex is off for this session. If a `mentat review`, `mentat challenge` or `mentat weigh` is running, stop it and say so.

## Pull requests

1. Do not call `mentat:review` or run `mentat review`, `mentat review --local` or `mentat review --grok`.
2. Once the test command passes on the head, push and update the description (Skill tool, `mentat:pr`). Its Checks give, for each numbered requirement of the spec, the check that covers it and what was observed (a hand check says who checked and what they saw), and says the maintainer turned Codex off for this session and the Claude review is still to come; do not claim a review yet. Step 4 updates it.
3. Run `mentat ci <N>`, which waits for CI on the head (up to 30 minutes; with no CI, about a minute) and reviews nothing itself. 0: go on. 3: the head moved; run it again. 4: failing checks: fix them, run the test command, push, and run it again; CI still running at the timeout: tell the maintainer. 1: tell the maintainer.
4. Review with Claude. Call the Skill tool with `code-review` and the args `medium <N>`. Always pass the level: a bare call reuses the last level typed. The level that runs can differ from the one passed, so take the level from the skill's own output. Never pass `--fix`, which would edit files in the main session, or `--comment`.
   - If the review runs in the background, wait for its result before posting. A review that fails, times out or returns nothing is not a pass; it falls under the last bullet.
   - Post that round's findings as one comment on the pull request, and say so when there are none. Start it with `Claude review round <n> on <sha>`, the head reviewed; with an external backlog it also records `Agreed request fingerprint: <12 hex>` of the current spec section's body, computed as `mentat:review` "Spec" says. The comment is the record of each round.
   - Sort each finding as `rules.md` "Findings" says. Batch the fixes into one brief for the `mentat:builder` subagent. When it reports, run the test command, push, update the description (Skill tool, `mentat:pr`), and run `mentat ci <N>` again.
   - Once the round's findings are settled, or there were none, update the description's Checks (Skill tool, `mentat:pr`) to say reviewed by Claude, not by Codex or Grok, with the level the skill reported, and keep the evidence per requirement.
   - One round by default. Run a second only to confirm the fixes of findings the first raised (a new head after a hold gets its own round regardless, unless waived: see below). Two rounds is the most per pull request; after a compaction or a resumed session, count the `Claude review round` comments already on the pull request. A real defect still unfixed after round two goes to the maintainer.
   - If the skill cannot be invoked or fails, do not stand in for it. The status line says "Not reviewed" and why, and the description's Checks are updated (Skill tool, `mentat:pr`) to say not reviewed and why.
5. Read the diff, the description and the linked issue from GitHub, not from memory (with an external backlog, the spec from the backlog through `mentat:backlog` instead of the linked issue), and correct any claim that does not hold, including a requirement of the spec that the Checks leave uncited, or a hand check that does not say who checked and what they saw. Rewrite the status line in full, its state Ready only if the Claude review ran and completed, else `Not reviewed: <why>` (it could not be invoked, failed, timed out or returned nothing), and in the note only its sentence on what stayed unfixed or was decided without the maintainer, adding "Reviewed by Claude (code-review, <level>), not by Codex or Grok", with the level the skill's own output reports and the model this session ran on (if the Claude review did not run and complete, "Not reviewed" and why instead), and, with an external backlog, that the Claude review has no `--request`, so it was not given the agreed request as a separate input (Skill tool, `mentat:pr`). If a hand check is open (a requirement checked by hand whose Checks row still does not say who checked it and what they saw), apply the hand check gate of `mentat:review`'s "Final check" (read through the Skill tool): the status line is `Blocked: <the hand check>` in place of Ready, step 6 does not run, and once the maintainer reports the check, step 5 runs again. A step the spec or the description says is done after the merge is no open hand check.
6. With no open hand check and an external backlog, mark the item as waiting on the merge of #N (`mentat:backlog` step 4). Tell the maintainer in chat: a first line "You: merge #N.", one more sentence (it was reviewed by Claude, not by Codex or Grok, or nothing reviewed it, if the review did not run) that also names a removal or reversal of something the maintainer asked for, when there is one, then each call made without them, one line each, and the pull request's link on the last line. Nothing else: the description's note is the full account. Stop.

On an agreed fast track (`mentat:propose`), the diff check of the "Fast track" section of `mentat:review` (which step 1 does not stop you reading through the Skill tool) runs on every push, including after a hold. If the diff still qualifies, step 4's Claude review is skipped, step 5's status line (with no open hand check; else `Blocked: <the hand check>`, and step 6 does not run) is `Not reviewed: fast track agreed by the maintainer`, and step 6's one sentence says nothing reviewed it: not Claude, Codex or Grok (fast track agreed by the maintainer). If it no longer qualifies, step 4's Claude review runs within its two rounds; `mentat review` never runs.

After "You: merge #N.", the hold, the answer to a hold, a close without merging and the merge itself work as in `mentat:review`'s "After "You: merge #N."" section: read that section through the Skill tool, without running the review loop. Here "five rounds" there means two Claude rounds. Where that section says to go to step 1 or run `mentat review`, go to step 3 here (`mentat ci`, then the Claude review); never run `mentat review` or `mentat review --grok`. A new head after a hold gets a Claude round of its own, even when the first round left nothing to confirm, from step 3 and within the same two rounds, through step 5 and a new "You: merge #N."; step 5 marks it Ready only if that review ran and completed on the new head. The one exception is a push whose round the maintainer waives (`mentat:review`, "Waived round", read through the Skill tool, which overrides this): step 3's `mentat ci` only, no Claude review, then steps 5 and 6 as that section says, with the last head a Claude round covered as the last reviewed head. With an external backlog, if the current spec's fingerprint differs from the last Claude round comment's, or that comment has none, a Claude round runs instead. A hold reply says in plain words, without #N outside its "Hold #N: <reason>" line, whether a Claude round remains; with none left, the status line is `Not reviewed: no review round left`.

Every description update here rewrites the status line in full and keeps the note's shape (`mentat:pr`). Whenever this path stops short of "You: merge #N.", first rewrite the status line with the state `Not reviewed: <why>` for step 3's tell-the-maintainer cases, or `Blocked: <the defect>` for an agreed defect still unfixed after round two (step 5 gives an open hand check's), and add the reason to the note in one sentence (for a defect, that it is agreed and still unfixed). Then tell the maintainer.

## Plans

When `mentat:propose` calls for `mentat:plan`, still write the plan, but do not run `mentat challenge`. The handoff says the plan was not challenged because the maintainer turned Codex off. The Claude review does not apply to plans. Likewise run no `mentat weigh`: give Claude Code's own view alone and say the weighing was skipped because the maintainer turned Codex off.
