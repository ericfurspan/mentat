The maintainer has turned Codex off for the rest of this session. Until the maintainer says in chat to turn Codex back on, these replace the Codex review loop (`mentat:review`) with one Claude review, and the plan challenge (`mentat:plan` step 2) and `mentat weigh` (`rules.md` step 2) with nothing; Claude Code's own view of a request still runs. Everything else in `rules.md` holds. After a compaction or a resumed session, Codex stays off; only the maintainer turns it back on, in chat. When they do, say in one line that Codex review is on again; that starts no review by itself. From then on the next review of any pull request, including one that had a Claude review round, goes through `mentat:review`: Codex reviews the head, and Grok reviews it too where it has not yet run on that pull request; a Claude review already running finishes and its findings are settled as usual.

When started, say in one line that Codex is off for this session. If a `mentat review`, `mentat challenge` or `mentat weigh` is running, stop it and say so.

## Pull requests

1. Do not call `mentat:review` or run `mentat review`, `mentat review --local` or `mentat review --grok`.
2. Once the test command passes on the head, push and update the description (Skill tool, `mentat:pr`). Its Evidence gives, for each numbered requirement of the spec, the check that covers it and what was observed (a hand check says who checked and what they saw), and says the maintainer turned Codex off for this session and the Claude review is still to come; do not claim a review yet. Step 4 updates it.
3. Run `mentat ci <N>`, which waits for CI on the head (up to 30 minutes; with no CI, about a minute) and reviews nothing itself. 0: go on. 3: the head moved; run it again. 4: failing checks: fix them, run the test command, push, and run it again; CI still running at the timeout: tell the maintainer. 1: tell the maintainer.
4. Review with Claude. Call the Skill tool with `code-review` and the args `medium <N>`. Always pass the level: a bare call reuses the last level typed. The level that runs can differ from the one passed, so take the level from the skill's own output. Never pass `--fix`, which would edit files in the main session, or `--comment`.
   - If the review runs in the background, wait for its result before posting. A review that fails, times out or returns nothing is not a pass; it falls under the last bullet.
   - Post that round's findings as one comment on the pull request, and say so when there are none. Start it with `Claude review round <n> on <sha>`, the head reviewed. The comment is the record of each round.
   - Sort each finding as `rules.md` "Findings" says. Batch the fixes into one brief for the `mentat:builder` subagent. When it reports, run the test command, push, update the description (Skill tool, `mentat:pr`), and run `mentat ci <N>` again.
   - Once the round's findings are settled, or there were none, update the description's Evidence (Skill tool, `mentat:pr`) to say reviewed by Claude, not by Codex or Grok, with the level the skill reported, and keep the evidence per requirement.
   - One round by default. Run a second only to confirm the fixes of findings the first raised. Two rounds is the most per pull request; after a compaction or a resumed session, count the `Claude review round` comments already on the pull request. A real defect still unfixed after round two goes to the maintainer.
   - If the skill cannot be invoked or fails, do not stand in for it. The status line says "Not reviewed" and why, and the description's Evidence is updated (Skill tool, `mentat:pr`) to say not reviewed and why.
5. Read the diff, the description and the linked issue from GitHub, not from memory (with an external backlog, the spec from the backlog through `mentat:backlog` instead of the linked issue), and correct any claim that does not hold, including a requirement of the spec that the Evidence leaves uncited, or a hand check that does not say who checked and what they saw. Rewrite the status line in full, its state Ready only if the Claude review ran and completed, else `Not reviewed: <why>` (it could not be invoked, failed, timed out or returned nothing), and in the note only its sentence on what stayed unfixed or was decided without the maintainer, adding "Reviewed by Claude (code-review, <level>), not by Codex or Grok", with the level the skill's own output reports and the model this session ran on, and, with an external backlog, that the Claude review has no `--request`, so it was not given the agreed request as a separate input (Skill tool, `mentat:pr`).
6. Tell the maintainer in chat, in a first line that names them: "You: merge #N." Say it was reviewed by Claude and not by Codex or Grok (or unreviewed, if the review did not run), and stop.

After "You: merge #N.", until the maintainer merges, #N's branch holds what they were told to merge. When later work belongs in #N (a change the maintainer asks for in #N, or one Claude Code finds #N should not merge without), push nothing yet: rewrite #N's status line with the state `Blocked: <reason>` first (Skill tool, `mentat:pr`), then reply with a first line "Hold #N: <reason>" and end the turn, saying whether a Claude review round remains for #N.

After the answer, if #N is still open and they want the work in it, build it on #N's branch (the `mentat:builder` subagent), run the test command and push. With a Claude review round left, update the description for the new head with the state `In review` (Skill tool, `mentat:pr`) and go to step 3 for the new head, within the same two rounds, through step 5 and a new "You: merge #N.": the new head gets a Claude round of its own, even when the first round left nothing to confirm, and step 5 marks it Ready only if that review ran and completed on the new head. With none left, rewrite the status line with the state `Not reviewed: no review round left` (Skill tool, `mentat:pr`) and tell the maintainer the new head was not reviewed, with no new "You: merge #N.". In any other case with #N open, first rewrite its status line back to the state it had before the hold (Skill tool, `mentat:pr`); then the work goes on a new branch from the default branch, in its own pull request.

No hold is needed for a question, when #N is merged or closed, or for work that stands apart from #N; any work then goes on a new branch from the default branch, in its own pull request.

Every description update here rewrites the status line in full and keeps the note's shape (`mentat:pr`). Whenever this path stops short of "You: merge #N.", first rewrite the status line with the state `Not reviewed: <why>` for step 3's tell-the-maintainer cases, or `Blocked: <the defect>` for an agreed defect still unfixed after round two, and add the reason to the note in one sentence (for a defect, that it is agreed and still unfixed). Then tell the maintainer.

The maintainer merges, as always.

## Plans

When `rules.md` step 2 calls for `mentat:plan`, still write the plan, but do not run `mentat challenge`. The handoff says the plan was not challenged because the maintainer turned Codex off. The Claude review does not apply to plans. Likewise run no `mentat weigh`: give Claude Code's own view alone and say the weighing was skipped because the maintainer turned Codex off.
