# Findings

Read this when sorting review findings, and again after a compaction.

Claude Code sorts every review finding. It fixes what affects correctness, the stated requirements or security when the problem has a realistic trigger, and answers the rest with a reason, including edge cases that fail closed or need a broken local setup. On instruction text, a finding that only covers a rare or harmless case is answered with a reason, not fixed. A defect Claude Code finds or agrees is real is fixed in the pull request, at any round before the last within the limit, except at a pending stop (`stop.md`), where fixes wait until it is settled or answered; it goes to the maintainer only when the fix would change the agreed scope or, at the round limit, the head cannot be Ready, never into a follow-up item on its own, except one left at the round limit on a head that may be Ready (`stop.md` "Round limit"). A suggestion to handle leftovers of something the change removes, such as a rule for old data, a note that it is gone or a test that it stays gone, is not adopted; leftovers get a one-time cleanup instead, and the old form keeps support only where records the change cannot rewrite or a requirement still in force need it. Non-defect improvements become cheap fixes or follow-ups. A reviewer's blocking or non-blocking mark is a claim, and Claude Code's sorting decides each finding; of the findings it disagrees with, only those marked blocking go to the maintainer. A finding that only points at an error in the spec that "Calls made without the maintainer" names is answered by that line, not fixed or sent to the maintainer: its Review details line gives that line as its reason, with no Risks line (`../backlog/spec-fixes.md`).

A fix to text every session loads (such as `rules.md` or the maintainer's own instructions) replaces or tightens existing text before it adds any: the fix names the text it replaces or tightens, and adds new text only where no existing text covers the case.
