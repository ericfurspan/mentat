# After "Ready to merge: #N"

Until the maintainer merges, if later work belongs in #N (a change the maintainer asks for in #N, or one Claude Code finds #N should not merge without), push nothing yet: rewrite #N's Status line with the state `Blocked: <reason>` first (Skill tool, `mentat:pr`), then reply with a first line "Hold #N: <reason>" and end the turn, saying in plain words, without #N, whether a review round remains.

After the answer, if #N is still open and they want the work in it, remove the item's merge wait where there is one (`mentat:backlog` "Marking a wait"), build it on #N's branch (the builder, its brief carrying the item's latest assumptions comment as given, when one exists, read through `mentat:backlog` "Material assumptions" right before the brief), run the test command when `rules.md` step 3 calls for it, and push. If the maintainer waives that push's round ("Waived round"), that section replaces the next two sentences. With a round left, update the description for the new head with the state `In review` (Skill tool, `mentat:pr`) and go to `mentat:review` step 1 for the new head, within the same five rounds, through `mentat:review` "Final check" and a new "Ready to merge: #N". With none left, rewrite the Status line with the state `Not reviewed: no review round left` and tell the maintainer the new head was not reviewed, with no new "Ready to merge: #N". In any other case with #N open, first rewrite its Status line back to the state it had before the hold; then the work goes on a new branch from the default branch, in its own pull request.

No hold is needed for a question, when #N is merged or closed, or for work that stands apart from #N; any work then goes on a new branch from the default branch, in its own pull request. When #N is closed without merging, remove the item's merge wait as above; its status stays.

When the maintainer says #N merged, do the steps of the item's wait block where there is one (`mentat:backlog` "Marking a wait"), then mark the item done, which ends its merge wait, do the repository's own post-merge steps, and report in one line, then end as `rules.md` "Ending finished work" says.

## Waived round

After Ready, Claude Code may propose skipping the review of a push the maintainer asked for that changes no file a program runs, sources or fetches; the diff is measured from the last head a review covered, and any doubt, a pushed diff that differs from the proposal, or a change to the spec runs the normal round; on their yes for that push, it runs `mentat ci` and `mentat:review` "Final check", the push uses no round, the Status line is `Not reviewed: last push waived by the maintainer`, and a Risks line and the merge message say it was waived and not reviewed.
