# After "Ready to merge: #N"

Until the maintainer merges, if later work belongs in #N (a change the maintainer asks for in #N, or one Claude Code finds #N should not merge without), push nothing yet: rewrite #N's Status line with the state `Blocked: <reason>` first (Skill tool, `mentat:pr`), then reply with a first line "Hold #N (<item id>): <reason>", without the parentheses when #N has no item, and end the turn, saying in plain words, without #N, whether a review round remains.

After the answer, if #N is still open and they want the work in it, end the item's merge wait where there is one, as the tracker's adapter says (`mentat:backlog` "Marking a wait"), implement it on #N's branch (the `mentat:builder` subagent, its model as `../build/helpers.md` "Briefs" says, its brief carrying the item's recorded assumptions as given, when any stand, read through `mentat:backlog` `Material assumptions` right before the brief), run the test command when `../build/helpers.md` "Testing" calls for it, and push. With a round left, update the description for the new head with the state `In review` (Skill tool, `mentat:pr`) and go to `mentat:review` step 1 for the new head, within the same round limit, through `mentat:review` "Final check" and a new "Ready to merge: #N". With none left, rewrite the Status line with the state `Not reviewed: no review round left` and tell the maintainer the new head was not reviewed, with no new "Ready to merge: #N". In any other case with #N open, first rewrite its Status line back to the state it had before the hold; then the work goes on a new branch from the default branch, in its own pull request.

No hold is needed for a question, when #N is merged or closed, or for work that stands apart from #N; any work then goes on a new branch from the default branch, in its own pull request. When #N is closed without merging, end the item's merge wait as above, and remove each manual check after the merge from its wait block, the whole block when nothing else is left in it, and the wait mark when no wait or blocking decision remains; its stage stays.

When the maintainer objects to the item's design, plan or pull request at a hold or a close without merging, the session that hears it writes one decisions line on the item recording each objection (`../backlog/agent-records.md` "Decision lines").

When the maintainer says #N merged, or this session has just merged #N (`merge.md`), do the steps of the item's wait block where there is one, except a manual check the spec marks as after the merge, which is the maintainer's (`mentat:backlog` "Marking a wait"), then mark the item done, which ends its merge wait as `mentat:backlog` "Marking a wait" says; when the spec marks a manual check as after the merge, end only any merge wait, as the tracker's adapter says, and keep each such check in the item's wait block, written at Ready as `ready-gate.md` says, or now if missing, so the item stays open and waiting instead, set back to In Progress if the tracker moved it to Done at merge. Then do the repository's own post-merge steps, delete #N's branch, and any clean worktree still on it, as `../build/helpers.md` "After merge" says. When the item stays waiting on such a check, give its steps in full as the whole turn, with no offer, then end. Otherwise report in one line, then end; where the maintainer's own instructions choose the "offer the next work" ending, read `../backlog/next-work.md` first: its offer, or its one line when nothing can start, takes the place of that report. In a session another session started, whichever ending applies also carries the after-merge reply its starting session asked for; after a merge of its own, that session sends its Merged line and the reply (each failed step, and whether a Mentat plugin update ran) to the starting session in one message. Inside a `mentat:build` run, the report goes into the run's final message and the run goes on.
