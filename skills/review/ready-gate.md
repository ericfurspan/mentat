# Ready gate

A manual check is open when a requirement of the spec is one the maintainer checks by hand, not one it marks as checked after the merge, and the description's Review details do not say the maintainer ran it and what was seen. Only the maintainer's run closes it, never an implementer's or Claude Code's own. Then say no "Ready to merge: #N": the Status line is `Blocked: <the manual check>`, Decisions and Risks has a risk line naming it (`mentat:pr`), the wait is written as `mentat:backlog` "Waits on the maintainer" says (with a backlog item, only on it plus one line right below the pull request's Status line; an external item is marked waiting, not as a merge wait), and the chat reply gives the wait's steps in full, as that section says. Once the maintainer reports the check passed, or runs it and the session judges its output meets the spec's pass condition (`mentat:backlog` "Waits on the maintainer"), record in Review details that the maintainer ran it and what was seen, remove the wait (`mentat:backlog` "Marking a wait"), its line and its risk line, and do the final check again; a failed result keeps the wait and is a defect to fix and check again. A step the spec or the description says is done after the merge stays in the item's wait block, where at Ready each manual check the spec marks as after the merge is written if missing, marked waiting (`mentat:backlog` "Waits on the maintainer"), its steps in full, saying it runs after the repository's own post-merge steps, in a new session; neither holds back "Ready to merge: #N".

With no open manual check: mark a draft ready (`gh pr ready <N>`). If the repository owner is not the author, request their review (`gh pr edit <N> --add-reviewer <owner>`) unless their latest submitted review is `APPROVED` with a commit oid equal to `headRefOid` (`gh pr view <N> --json reviews,headRefOid`; not `reviewDecision`); if that read fails, request it. Then read `mentat status <N>`: while it fails, its `owner review:` is `not requested` or `unknown`, or its `calls section:` (the Decisions and Risks heading, or an older pull request's "Calls made without the maintainer") is `missing` or `unknown` (when `missing`, first add the section, `mentat:pr`, and read again), rewrite the Status line with the state `Blocked: mentat status failed (<why>)` when status itself fails, else `Blocked: owner review <its value>` for the owner review and `Blocked: calls section <its value>` for the calls section, both when both fail (Skill tool, `mentat:pr`), give no "Ready to merge: #N", start no merge wait, and tell the maintainer which and why instead; once it reads otherwise, do the final check again. Otherwise, move each decision in any open "Decision for the maintainer" section to a Backlog item (`mentat:plan` "Decisions"), reusing one already filed for it; a write that fails twice does not hold back the Ready line, and the Ready message then adds a sentence quoting each such decision word for word as not moved. Then, with an external backlog, start the item's merge wait as the tracker's adapter says (`mentat:backlog` "Marking a wait").
