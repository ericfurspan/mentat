---
name: review
description: "Review loop for a pull request: running mentat review, acting on its result, and the final check. Use when a pull request is built, its tests pass and it is pushed, and after every push of review fixes."
---

Codex reviews each head commit of the pull request, and Grok, where installed, the first. Claude Code sorts the findings, fixes and pushes, and reviews again until the loop ends. Then it posts the final check, and the maintainer merges.

## When the loop ends

- **Ready:** the review exits 0 on the latest commit, or exits 2 and every finding was fixed or answered with a reason, none is a real defect left unfixed, and none is a blocker Claude Code disagrees with; and Claude Code has read and answered every comment and review the maintainer left, and, where this session started Grok, its `mentat review --grok` has ended. Do the final check below, then stop.
- **Blocked:** a blocking finding Claude Code disagrees with goes to the maintainer.
- **Not reviewed** after the local path: tell the maintainer.
- **Hard stop:** five review rounds per pull request, counting rounds before a compaction or a resumed session. A round is a review that exits 0 or 2; a fallback to local review, a moved head and a CI failure are not rounds. If round five is not ready, settle its findings (fix agreed defects and run the tests), then stop without a sixth round and tell the maintainer why, naming any real defect still unfixed and any head not yet reviewed.

Each round's result is on the pull request (the review and the replies to it). With an external backlog (`rules.md` Records), every review that exits 0 or 2 counts toward the five rounds, whatever its fingerprint. The comment's `Agreed request fingerprint` line only says whether that review covered the current agreed request (see "Agreed request"); `none` or a different value does not, so another round is needed, within the same limit. After a compaction or a resumed session, count the rounds from there before continuing. A `Local Codex review of <sha>` comment whose last non-blank line is `REVIEW RESULT: INCOMPLETE - ...` is not a round: sort its findings as step 3 says, and give its reason to the maintainer as a limitation, as the exit 1 path does.

## Steps

1. Run `mentat review <N>`, or `mentat review --local <N>` when the repository's AGENTS.md says reviews are local, right after pushing. With an external backlog, see "Agreed request" instead: its reviews are always local. Both first wait for CI on that head (up to 30 minutes; with no CI, about a minute). The app path comments `@codex review` on the pull request, which starts the Codex app's review of that exact head (OpenAI's page says the app flags only P0 and P1 issues, though it has posted P2s), and reads the result from the app's summary comment for that commit, counting security-review findings too; the local path reviews that head with local Codex and posts the result on the pull request. Both wait for the result.
2. With an external backlog, every round that exits 0 or 2 gets the round's comment link and the settlement on the item (`mentat:backlog`), not the review body; a clean round's settlement says there were no findings. Exit 1, 3 and 4 post nothing. Act on the exit code:
   - 0: no findings. Go to "When the loop ends".
   - 2: findings were posted on that commit. Go to step 3.
   - 1: not reviewed. After the app path, run `mentat review --local <N>`; after the local path, tell the maintainer. If local Codex ended `REVIEW RESULT: INCOMPLETE - ...`, its reason is in the posted reply: give the maintainer the reason with the reply, as a limitation, not a finding. Any findings in that reply are still sorted as step 3 says (fixed or answered with a reason) before you tell the maintainer.
   - 3: the head moved. Run the same command again.
   - 4: CI did not pass on that head, and nothing was reviewed. Failing checks: fix them, push, and run the same command again. CI still running at the timeout: tell the maintainer.
3. Sort each finding as `rules.md` "Findings" says, Grok's with Codex's (see "Grok"). The round number does not change how a finding is sorted. A review that fails, times out or returns nothing is not a pass. There is no check-in with the maintainer between rounds.
4. Batch the fixes into one brief for the `mentat:builder` subagent (a new dispatch, or continuing the earlier builder). When it reports, run the test command on a clean working tree (`git status --porcelain` prints nothing) on the commit being pushed, push, and update the description (Skill tool, `mentat:pr`). Then go to step 1 for the new head, unless the round limit says to stop. A result on an older head does not make the new head ready.

## Grok

When `grok` is installed (`mentat check` prints its version), the first head also gets `mentat review --grok <N>`, run in parallel with step 1's Codex review. Grok has its own time limit (`MENTAT_GROK_TIMEOUT_SECONDS`, default 30 minutes) and real runs have taken over 20, so do not wait for it: when Codex's round finishes first, sort its findings, push their fixes and go on with the loop; when Grok's result arrives, sort its findings and fold any fixes into the next Codex round. A finished Grok review is posted for the commit it reviewed even if the head has moved since. Ready still waits for a Grok run this session started to end. Grok is not a round: it does not count toward the five and is not run again on later heads. Its exit codes are the review's: 0 no findings, 2 findings posted on the pull request, 1 not reviewed (Codex carries on alone, except for a sign-in refusal, below), 3 the head moved, 4 CI did not pass. A Grok reply ending `REVIEW RESULT: INCOMPLETE - ...` is not reviewed too: Codex carries on alone, the final check records the limitation, and any findings in that reply are still sorted.

- Look for a `Grok review started on` comment on the pull request before running it. Count only comments posted by the account `gh` is signed in as (`gh api user --jq .login`); anyone who can comment could post the same text. `mentat review --grok` applies the same rule and exits 1 when its own account's start comment is already there. If there is none and the run exits 3 or 4, run it again for the next head, as the loop does for Codex.
- A not-reviewed reason that starts with `Grok's sign-in` or `Grok is not signed in` is a refusal before Grok started, not a review that ran: no start comment was posted, so Grok may still run. It is not skipped. Ask the maintainer to run `grok login`, in a message that ends the turn, while Codex's loop goes on; once they say it is done, run `mentat review --grok <N>` on the current head. Ready waits for that run to end.
- Once a start comment exists, never start Grok on that pull request again. After a compaction or a resumed session, decide from the pull request's comments, again only this account's: a start comment followed by `Local Grok review of <sha>` means Grok is done, unless that review's last non-blank line is `REVIEW RESULT: INCOMPLETE - ...`, which is an incomplete review, not one that did not run: Grok did not finish and Codex's loop goes on without it, its reason is kept for the final check, and any findings in that reply are sorted like any Grok finding; a start comment with `Grok review did not finish on <sha>`, or with no result, means Grok did not finish, and Codex's loop, including Ready, goes on without it.
- Grok's findings are sorted like Codex's: fix what is a real defect, answer the rest with a reason. With an external backlog, when Grok's result arrives (exit 0 or 2), post its review comment's link and the settlement of its findings on the item (`mentat:backlog`). A fix is pushed with the next Codex round's fixes, not reviewed by Grok again.

## Agreed request

With an external backlog, the agreed request is in the backlog item, not in a linked issue (`mentat:backlog`). Codex and Grok get it as a separate input, apart from the description. Reviews there are local by choice: Mentat builds that prompt itself, and whether the Codex app reads a full request in its comment is unverified. Before each review, read the item's "Agreed request" section through `mentat:backlog`, copy it unchanged into a `mktemp` file, and run `mentat review --local --request <file> <N>` (step 1's command) and `mentat review --grok --request <file> <N>` ("Grok"); remove the file afterwards. A review run without `--request` there still uses up a round but does not cover the request. `--request` without `--local` or `--grok` is a usage error (exit 64). Each local review comment records `Agreed request fingerprint: <first 12 hex characters of the SHA-256 of the request text>`, or `none`. To compare, write the current section to a file and run `printf '%s' "$(cat <file>)" | shasum -a 256 | cut -c1-12`.

## Final check

Once the loop ends ready, read the diff, the description and the linked issue (with an external backlog, the current agreed request from the backlog instead) from GitHub, not from memory, and correct any claim in the description that does not hold. With an external backlog, compare the fingerprint in the head's Codex review (and in Grok's, where it ran) with the current section's: a missing or different one does not cover that request, so run another round first, within the five-round limit; where Grok's differs, say so in the comment. Then post one comment on the pull request, six lines at most, that does not repeat the description's summary or scope: the commit checked and its test and CI results, the one-sentence statement of the pull request's intent from the last review that gave one (Codex's, or Grok's where it ran; written by Claude Code from the request and the diff, and said to be, if none did) and whether it matches the description's (and, with an external backlog, the agreed request's), how each review finding was settled (Codex's and, where it ran, Grok's, or that Grok did not run), what was not checked, and what most deserves the maintainer's eyes. The comment is the author's own check, not a review or an approval. Start it with `Final check on <sha>`, the commit checked.

If the pull request's author is not the repository owner, request the owner's review with `gh pr edit <N> --add-reviewer <owner>`. Then tell the maintainer in chat, in a first line that names them: "You: merge #N." Stop. The maintainer merges.
