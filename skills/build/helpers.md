# Helper builds

Read this before briefing a builder and before each push, and again after a compaction or a resume. It covers every builder run: the initial build, CI fixes, review fixes and work after a hold alike.

## Briefs

The builder is the `mentat:builder` subagent. A brief names any existing design the change keeps that could affect its goal.

Right before every `mentat:builder` call, a build, a CI fix and a review fix alike, read `MENTAT_BUILDER_MODEL` by name with `printenv MENTAT_BUILDER_MODEL`, never the whole environment, and pass its value as the call's model; unset or empty, the call sets no model and the builder definition's own model runs.

Before fixing a raised problem, Claude Code checks likely related cases in proportion to its scope and reports a shared cause when found, keeping the fix within the agreed scope. A fix it recommends targets the cause the evidence supports; when the cause is unknown, it recommends finding the cause first.

A correction during agreed work does not reopen the spec; a change of scope, or an outcome the spec leaves open (what the maintainer gets, pays or risks), goes to the maintainer as one question before that part is built. Claude Code follows any correction within the agreed scope at once, and files it as an item only when the maintainer asks.

## Worktree

The session makes no worktree for a builder. After `git fetch origin`, before the first builder starts, cut the item's branch as a ref with `git branch --no-track <branch> origin/<default>`. Keep `--no-track`: without it the branch tracks the default branch, so a bare `git push` would aim at it. The branch carries the item id as the tracker's adapter says. Each builder runs in a worktree the host makes for it, switches to the branch there and reports that worktree's absolute path, the `<path>` below.

The main session never changes its own directory into a worktree: it runs `git -C <path>` or a subshell `( cd <path> && ... )`. It pushes with `git -C <path> push -u origin <branch>` once the round is finished ("One helper per branch") and `git -C <path> status --porcelain` prints nothing; the pushed head is `git -C <path> rev-parse HEAD`, which `mentat review` then reads from GitHub. After the push it removes the clean, pushed worktree with `git worktree remove <path>`, never `--force`; a refusal keeps the worktree and lists it as unfinished, and no builder starts on a branch while a worktree is on it. Between rounds a pull request has no worktree.

## One helper per branch

A pull request has one builder at a time, which is what `rules.md` means by one builder per pull request: each round of it (the first build, CI fixes, review fixes, work after a hold) is a fresh `mentat:builder`, started in the background, so the session stays free. The brief names the branch, the session's own checkout and the main checkout (the parent of `git rev-parse --path-format=absolute --git-common-dir`). While the builder runs, the host's lock on its worktree is the lock; the session adds none. When its completion notice arrives, done, stopped or failed, run the main-checkout check. A round is finished only when its builder's report says the brief's work is done and committed. Any other report says the builder stopped short, and it finishes nothing: nothing of that round is tested, pushed or reviewed. The round then goes on as "Unfinished" says, or, where no worktree is on the branch, with a fresh builder as "Recovery" says for an unfinished round; the builder that goes on with it, the same one or a fresh one, is given what the report said stopped the round. Only a stop the session cannot resolve without the maintainer (a failed start-up check, a permission block) goes to them first: its worktree is kept as it is, and the round goes on the same way once they answer. A builder that ends with no report leaves its round unfinished, handled as "Recovery" says for a branch with no running builder. The next round starts a fresh builder on the branch.

## Main-checkout check

Before each brief, note the main checkout's branch, `HEAD` and status with `git -C <main> branch --show-current`, `git -C <main> rev-parse HEAD` and `git -C <main> status --porcelain -- ':(exclude).claude/worktrees'`, `<main>` being the main checkout as "One helper per branch" defines it. Where the session's own checkout is another directory, note its branch, `HEAD` and status the same way with `git -C` on it, since a builder must change neither. After the helper reports, compare each checkout with the note taken for that helper's brief; the next brief notes it as it is then. It is unchanged when its branch is the noted one, its status prints what was noted (nothing, for one clean before the brief), and its `HEAD` is the noted one, or else moved only forward along origin's copy of that branch as last fetched (no fetch first), which holds when `git -C <checkout> merge-base --is-ancestor <noted HEAD> <new HEAD>` and `git -C <checkout> merge-base --is-ancestor <new HEAD> origin/<branch>` both succeed, `<checkout>` being that checkout and `<branch>` its noted branch. If a checkout was not clean before the brief, the run's final message says the check was weaker. On any other difference, start no further helper, change nothing in either checkout, and tell the maintainer the paths and what changed. The check does not see writes to ignored paths.

## Testing

Before pushing, Claude Code tests the pushed commit, with a clean working tree (`git -C <path> status --porcelain` prints nothing), not relying on the builder's report, unless the repository's AGENTS.md says CI runs the test command on every pull request. Then CI is that run, except that after CI fails on the branch, the next commit is tested this way before it is pushed; and when that run was skipped, a head with no CI check runs is not a pass: Claude Code tests that commit before any review of it counts, in a test worktree at a temporary path outside every checkout (`git worktree add --detach <temporary path> <commit>`, the test command there with its output saved outside it, then `git worktree remove <temporary path>`; a refusal keeps it, listed for the maintainer), never in the main checkout or the session's own.

## Recovery

After a compaction or a resume, before any other build step, find this session's work by its items' branches (its build queue, or the item it agreed), not by worktree paths. Read `git worktree list --porcelain`. For each such branch, read the worktree checked out on it, if any, with `git -C <path> status --porcelain`, its commits not on origin's copy of the branch, and its pull request (`gh pr list --head <branch> --state all --json number,state,headRefOid`), with `mentat status <N>` for an open one.

A builder counts as running only while the host's list of this session's subagents shows it running and its report is not yet in the session: wait for that report. If that list cannot be read, wait for the report and tell the maintainer. A worktree on one of these branches is this session's. For each branch with no running builder, first decide whether a round is unfinished: one this session started that is not finished ("One helper per branch"), by the session's own record of the run, or the first round of a queue item's branch with no pull request and no commit beyond the default branch's, which no builder has built on yet. Where the record cannot tell, start no builder on that branch, remove no worktree and tell the maintainer. With an unfinished round, a worktree on the branch is handled as "Unfinished", whatever its state, never removed as clean and pushed; with no worktree, a fresh builder gets that round's brief, for a first round the item's, and is told of any earlier builder that stopped. A round that waits for the maintainer's answer on a stop ("One helper per branch") waits for it here too: start no builder and remove no worktree until they answer. With no unfinished round, a worktree still on the branch is removed as "Worktree" says when it is clean and pushed, else handled as "Unfinished"; with none, start no builder and go on with the step the pull request was at (its review, a wait on the maintainer, or after merge). Every other worktree, locked or not, is left untouched and listed for the maintainer. A host-made worktree whose builder never switched holds no work and is left to the host.

## Unfinished

A builder's worktree is unfinished when it has uncommitted changes or commits not pushed, or its round is not finished ("One helper per branch"). It is never reset, stashed, cleaned or force-removed. When its round is finished and `git -C <path> status --porcelain` prints nothing, it needs no builder: start none and go on with the step it waited for (test, push, then removal as "Worktree" says). While its round waits for the maintainer's answer on a stop ("One helper per branch"), keep it as it is. Otherwise continue that same builder where the host still knows it. Where the host does not, commit any uncommitted work as it stands onto the item's branch with `git -C <path> add -A` and `git -C <path> commit`, with a subject saying an earlier builder stopped; then, whether or not there was anything to commit, remove the worktree with `git worktree remove <path>` once `git -C <path> status --porcelain --ignored` prints nothing, and start a fresh builder, told that an earlier builder stopped and that its work stays where it fits the brief. Commits already on the branch stay there. Ignored files left in that worktree may be the stopped builder's work, which no report has named (after a push the report has, so that removal stays plain): keep the worktree, list it with those paths, and go on with the removal and the fresh builder once the maintainer says to drop them. When a step of this is refused, keep the worktree and list it, one line each (path, branch, what is unfinished), in the recovery message and in the build run's final message.

## After merge

Act only on this session's branches as "Recovery" defines them; leave another session's untouched and list it. When the maintainer says #N merged, or the recovery read finds it merged, and `gh pr view <N> --json state,headRefOid` shows `MERGED` with the head equal to the branch's pushed head and to `git rev-parse <branch>`, delete the item's local branch with `git branch -D <branch>`: the pull request's state shows it merged, not ancestry, since a squash merge leaves the branch unmerged to git. A worktree still on that branch is removed first with `git worktree remove <path>` (never `--force`), only when `git -C <path> status --porcelain --ignored` prints nothing, and never the checkout this session runs in or one with another worktree's path under it in `git worktree list`; otherwise keep it, and its branch, and list it with those paths. A refusal keeps the worktree and lists it as unfinished. A branch whose pull request closed without merging is kept and listed until the maintainer says to drop it. The remote branch is left alone.

## A separate session

A build runs in a separate session only as `mentat:propose` "Starting a build" says.
